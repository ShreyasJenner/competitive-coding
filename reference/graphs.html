Graphs

Quick reference · C++ · sources: CPH ch. 12, USACO Guide: Flood Fill

Spot it

  • A grid where cells “touch” or “spread” to their neighbours
  • The question asks how many groups, how big, or can A reach B
  • Words like connected, adjacent, region, island, component
  • Examples: 200, 695, 733, 130

Glossary

TermMeaning here
nodeone cell (r, c), or one vertex of a general graph
edgetwo nodes that are directly connected; in a grid, land cells sharing a side (not a corner)
connected componentevery node reachable from a start node; an “island”
scanthe outer loop over every cell; the only place that counts
fill (flood fill)a DFS from one cell that marks its whole component
mark / visiteda flag set on arrival so that a node is expanded once

The rule

Mark a node the moment you arrive, before touching any neighbour. Every call checks the mark first. if (visited[s]) return; visited[s] = true; (CPH §12.1)
  • Trees (301, 1106) can’t revisit a node. Grids and graphs can, because they have cycles.
  • Mark with a separate visited array, or by overwriting the input ('1' → '0').

Grid as graph

const int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1};   // 4 directions
for (int d = 0; d < 4; d++) {
    int nr = r + dr[d], nc = c + dc[d];
    if (nr < 0 || nc < 0 || nr >= m || nc >= n) continue;  // bounds BEFORE reading grid
    // ...
}

Scan + fill: for each cell, if it’s unmarked land, count++ and fill from it. (Lesson 5)

Pitfalls

BugSymptom
mark after recursing (or never)two neighbours call each other forever; ASan stack-overflow
reading grid[r][c] before the bounds checkASan heap-buffer-overflow at the edges
8 directions instead of 4diagonal neighbours merge; 10/01 gives 1, not 2
counting inside the fillcounts cells, not islands
passing visited or the grid by valuea full copy on every call, so O((mn)2) time and memory

Cost

Time O(mn): each cell is expanded once and checked at most four more times. This is DFS’s O(n+m) with mn nodes. The recursion depth can reach the island’s size (about 45,000 for a 300×300 snake), which is fine for LC 200. For much larger grids, use an explicit stack or BFS (USACO warns about this).

Template (LC 200)

void fill(std::vector<std::vector<char>>& g, int r, int c) {
    if (r < 0 || c < 0 || r >= (int)g.size() || c >= (int)g[0].size()) return;  // off the grid
    if (g[r][c] != '1') return;                    // water, or already marked
    g[r][c] = '0';                                 // mark ON ARRIVAL
    for (int d = 0; d < 4; d++) fill(g, r + dr[d], c + dc[d]);
}

int numIslands(std::vector<std::vector<char>>& g) {
    int count = 0;
    for (int r = 0; r < (int)g.size(); r++)
        for (int c = 0; c < (int)g[0].size(); c++)
            if (g[r][c] == '1') { count++; fill(g, r, c); }  // only the scan counts
    return count;
}
  • Guard placement: either reject at the top of fill (above), or check bounds before each call. Both are correct; the guard-at-top style pairs with a direction loop.
  • Sinking to '0' merges “water” and “already seen” into one check.
  • Returning a value instead (e.g. island size for 695): return 1 + sum of the four calls, and 0 when rejected.

Template (LC 695): the fill returns a value

int area(std::vector<std::vector<int>>& g, int r, int c) {
    if (r < 0 || c < 0 || r >= (int)g.size() || c >= (int)g[0].size()) return 0;
    if (g[r][c] != 1) return 0;                    // water or seen: adds nothing
    g[r][c] = 0;                                   // mark ON ARRIVAL
    int size = 1;                                  // me
    for (int d = 0; d < 4; d++) size += area(g, r + dr[d], c + dc[d]);  // + my children
    return size;
}

int maxAreaOfIsland(std::vector<std::vector<int>>& g) {
    int best = 0;
    for (int r = 0; r < (int)g.size(); r++)
        for (int c = 0; c < (int)g[0].size(); c++)
            best = std::max(best, area(g, r, c));     // the max lives in the scan only
    return best;
}

  • With an accumulator, the result never goes down, so max(tmp, f) inside the fill is always just tmp.
