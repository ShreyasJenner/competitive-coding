Recursive Descent

Quick reference · C++ · source: Crafting Interpreters §6.2

Spot it

  • Input is a string with nested brackets that you must evaluate, decode or build a structure from
  • The statement gives a grammar (“X is either … or op(X, X, …)”)
  • The first character of each piece decides what kind of piece it is
  • Examples: 1106, 394, 385, 224, 726

The contract

parse(s, i) reads exactly one expression starting at s[i], returns its value, and leaves i just after it.
  • One function per grammar rule. Branch on the first character.
  • The cursor is shared: use int& i or a member, never a copy.
  • After a child returns, the caller looks only at s[i] (a separator or a closing bracket) to decide what comes next.

(Lesson 4)

Pitfalls

BugSymptom
cursor passed by valuecaller re-reads the child, then runs off the end or loops
early return once the value is knowncursor stuck inside the brackets, so the parent misreads the leftovers
forgetting to step past )parent sees ) and ends its own list too soon

Cost

Time O(n): each character is consumed once. Stack depth equals the nesting depth, at most about n/3 for !(…)-style grammars. For n ≤ 2·104 that’s fine. For much deeper input, switch to an explicit stack.
