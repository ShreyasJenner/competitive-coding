Trees

Quick reference · C++ · sources: CPH ch. 14, CPH §18 (LCA)

Spot it

  • The input is a TreeNode* root, or a graph with n nodes and n−1 edges
  • The answer for a node depends on the answers for its subtrees: size, height, sums, “does it contain X”, “where do two paths meet”
  • Examples: 236, 104, 543, 124

The shape

Each call answers for its own subtree and returns that answer. The parent combines its children’s answers. It doesn’t look past them. (Lesson 6)
R f(TreeNode* t) {
    if (!t) return /* answer for an empty tree */;
    R a = f(t->left), b = f(t->right);
    return /* combine t, a, b */;
}

Template (LC 236)

// Contract: f(t) returns nullptr if t's subtree holds neither p nor q,
// the one it holds if only one, and their LCA if both (which may be deep below t).
TreeNode* lowestCommonAncestor(TreeNode* t, TreeNode* p, TreeNode* q) {
    if (!t || t == p || t == q) return t;          // empty, or landed on a target
    TreeNode* a = lowestCommonAncestor(t->left, p, q);
    TreeNode* b = lowestCommonAncestor(t->right, p, q);
    if (a && b) return t;                          // one on each side: t is where they meet
    return a ? a : b;                              // pass up whatever was found (or null)
}

Verified 18/18 (./test.sh 236). Time O(n), stack O(h). Compare: walkccc 236.
