Backtracking

Quick reference · C++ · source: CPH ch. 5

Spot it

  • “Return all …” or “generate every …”
  • Small input (n ≤ ~25) means 2n or n! is fine
  • The answer is built one decision at a time (include/exclude, keep/delete, place/skip)

Template

void dfs(int i, State st) {
  if (dead(st)) return;          // prune: can't reach a good leaf
  if (i == n) {                  // leaf
    if (good(st)) record(path);
    return;
  }
  for (Choice c : choices(i, st)) {
    apply(c);                    // choose
    dfs(i + 1, next(st, c));     // explore
    undo(c);                     // un-choose
  }
}

DFS over choices

A node is one call plus its state, and its children are the recursive calls it makes, one per choice. The tree is never stored; it exists only as the call stack. Shared state (like path) must be restored before returning: choose, explore, un-choose. State passed by value (like budgets) needs no undo. (Lesson 2)

void dfs(int i) {            // all subsequences: 2^n leaves
  if (i == n) { out.push_back(path); return; }
  dfs(i + 1);                // delete s[i]
  path.push_back(s[i]);      // keep s[i]
  dfs(i + 1);
  path.pop_back();
}

Leaves come out in “binary counting” order: s[0] is the slowest-changing choice.

Pruning checklist

  1. Can you compute a budget up front (the minimum cost, or the count of each thing to remove)? Never overspend it.
  2. Is there an invariant that, once broken, can never be repaired (balance < 0, sum > target)? Cut there.
  3. Can different paths produce the same output? Skip equal siblings (below). A set is the fallback, but it throws work away instead of avoiding it.

Skip equal siblings

Equal characters are interchangeable, so only how many you take from a run matters. Build one representative. (Lesson 3)

Cost

Binary choices give O(2n) leaves, times O(n) to copy each accepted string. Pruning helps a lot in practice but doesn’t change the worst case.
