Backtracking

Quick reference · C++ · source: CPH ch. 5

Spot it

  • “Return all …” or “generate every …”
  • Small input (n ≤ ~25) means 2n or n! is fine
  • The answer is built one decision at a time (include/exclude, keep/delete, place/skip)

Template

void dfs(int i, State st) {
  if (dead(st)) return;          // prune: can't reach a good leaf
  if (i == n) {                  // leaf
    if (good(st)) record(path);
    return;
  }
  for (Choice c : choices(i, st)) {
    apply(c);                    // choose
    dfs(i + 1, next(st, c));     // explore
    undo(c);                     // un-choose
  }
}

Pruning checklist

  1. Can you compute a budget up front (the minimum cost, or the count of each thing to remove)? Never overspend it.
  2. Is there an invariant that, once broken, can never be repaired (balance < 0, sum > target)? Cut there.
  3. Can different paths produce the same output? Dedupe with a set, or skip equal siblings.

Cost

Binary choices give O(2n) leaves, times O(n) to copy each accepted string. Pruning helps a lot in practice but doesn’t change the worst case.
