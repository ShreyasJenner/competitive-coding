LC 236 Lowest Common Ancestor: each call reports what its subtree contains, and the parent makes the decision

Your win today: find the lowest common ancestor in a tree of 105 nodes in one pass, using a function whose return value means something you chose. Most tree Mediums come down to the same question: “what should a call hand back?”

0. Warm-up from 695

Your 695 fill returned 1 + the sum of its neighbours’ returns. Use the same idea on a tree: let size(t) be 0 for an empty child, and otherwise 1 + size(left) + size(right). CPH computes count[s] exactly this way (§14.1, PDF p. 145). Answer from the picture:

What does each call return?

2 has the leaves 7 and 4 under it: 1 + 1 + 1 = 3. Node 5 is 1 + size(6) + size(2) = 1 + 1 + 3 = 5. The root adds node 1’s three: 1 + 5 + 3 = 9. No call looks past its own children. Each one trusts what they report, just as each 695 fill trusted its neighbours.

1. What “lowest common ancestor” means

“The lowest common ancestor of two nodes of a rooted tree is the lowest node whose subtree contains both the nodes.” (CPH ch. 18, PDF p. 177)

LeetCode adds one rule: a node counts as its own descendant. So if q is below p, the answer is p. Use the tree above:

LCA of each pair:

p=5, q=1
p=7, q=4
p=5, q=4
p=7, q=8

5 and 1 are on opposite sides of 3. 7 and 4 are siblings under 2. 4 is inside 5’s subtree, and 5 counts as its own descendant, so the answer is 5. 7 is deep on the left and 8 is on the right, so they meet only at the root.

The brute force asks every node “are both p and q in your subtree?” and keeps the deepest node that says yes. Each question is its own search, so the cost is O(n²) on a long thin tree, which is too slow at 105. The redundant work is that a node’s search repeats its children’s searches. So let the children report instead.

2. Design the contract

You’ll write f(t), which looks at t’s subtree once and returns something to its parent. Before you open the box below, decide what that something is. Write it down in one sentence.

A bool (“I found p or q”) is a natural first try. It doesn’t work: when the root hears true from both sides, it knows the answer is the root. But when it hears true from one side only, it knows the answer is somewhere down there, and not which node. The return value has to carry a node.

The contract (open once you’ve written yours)

f(t) returns a TreeNode*:

What t’s subtree containsf(t) returns
neither p nor qnullptr
exactly one of themthat node
boththeir LCA

The meaning changes from row to row, and that is fine. The parent only needs to tell “nothing” from “something”, then decide. If the root’s whole tree holds both nodes, its row is the last one, so f(root) is the answer.

3. Check yourself: the parent’s decision

These follow from the contract alone. In each one, t is neither p nor q.

1. f(t->left) returned 7 and f(t->right) returned 4. What does f(t) return?

Each side holds one target, so they are on opposite sides of t, and t is the lowest node that contains both. Besides landing on p or q itself (quiz 3), this is the only place an LCA is created. Everywhere else, a node is passed up.

2. f(t->left) returned null and f(t->right) returned 8. What does f(t) return?

t’s subtree holds whatever the right side found, and nothing else. That is either one target or an LCA found further down. Either way, the contract says hand it up as it is.

3. When a call lands on p, it can return p at once, without searching below. Why is that still correct if q is below p?

If q is below p, the LCA is p (row 3 of the contract). If it isn’t, searching below p is wasted work, because some ancestor will get p from one side and q from the other. Either way, “return p” is correct.

4. On a tree with n nodes and height h, what does f(root) cost?

Each node gets one call that does O(1) work besides its two child calls, so the brute force’s repeated searches are gone. The stack holds one frame per level, so h is about log n when the tree is balanced and n when it is a long vine. Unlike a grid, a tree has no cycles, so nothing needs marking (CPH §14.1).

4. See it

Step through it. The blue nodes are p and q, the red ring is the running call, and the red label under a node is what its call handed back. Try p=5, q=4: watch the search stop at 5 without going down to 4. Then try two leaves on opposite sides, such as 7 and 8.

Hint 1

You may not need a helper. lowestCommonAncestor already takes a subtree’s root and returns a TreeNode*. Does it satisfy the contract if you call it on root->left?

Hint 2

There are two base cases, both before any recursion: an empty subtree, and landing on p or q (quiz 3).

Hint 3

After both child calls there are three cases: both sides non-null, one side non-null, or neither. Quizzes 1 and 2 are two of them.

Compare pointers (root == p), not values. The values happen to be unique, but the answer has to be a node of this tree, and the tests check that by pointer.
