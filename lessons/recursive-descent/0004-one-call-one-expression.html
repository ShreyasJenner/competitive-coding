One Call, One Expression

LC 1106 · the tree is written in the string, so read it with one call per node

Your win today: a recursive parser of about 20 lines for LC 1106 that passes all 14 local cases. Those include 6,666 levels of nesting and 3,000 random expressions.

1. The string is a tree

In Lesson 2 the tree existed only in the call stack. Here it is spelled out in the input. Every operator is a node, and its children are the expressions between its brackets, separated by commas (problem statement):

Predict, using s = "|(&(t,!(f)),f)" (indices 0–13). Answer the last two from the string alone, without the figure.

children of |
value of s
expr at s[2]
expr at s[6]

!(f) is t, so &(t,t) is t, and |(t,f) is t. The expression at 2 is &(t,!(f)), which closes at 10, so whatever reads it should stop at 11, the comma. The expression at 6 is !(f), which closes at 9, so the next index is 10.

2. The contract

The last two questions are exactly the work your function has to do. Write one function and hold it to this promise:

parse reads exactly one expression starting at the cursor, returns its value, and leaves the cursor on the character just after it.

The promise makes the caller simple. After a child returns, the caller doesn’t need to know how long that child was: the cursor is already on a , (more children follow) or a ) (that was the last one). The first character alone tells you which grammar rule you are in:

s[i]shapechildren
t fone characternone
!!( expr )exactly 1
& |op( expr { , expr } )1 or more

One function per grammar rule, with a cursor moving forward through the input, is called recursive descent. Nystrom describes it as a parser that is a direct translation of the grammar into code (Crafting Interpreters §6.2). His parser keeps the same kind of cursor: current “points to the next token eagerly waiting to be parsed.”

The input is guaranteed valid, so you need no error handling. That is the only reason the code stays short. Real parsers spend most of their lines on malformed input (§6.3 of the same chapter).

3. See it

Step through it. The highlighted cell is the cursor. The underline marks what the running call has consumed so far. Every return leaves the cursor just past the underline. You can also type your own expression.

4. Check yourself

1. Why must the cursor be int& (or a member), and not a plain int?

The child’s progress is half of the contract. With a copy, the child advances its own i, and the caller’s cursor stays on the child’s first character. In the test, this version runs off the end of the string on the very first case. Compare Lesson 2, where budgets should be copies: there each child gets its own value, but here every call shares one position in one string.

2. In &(f,…) the answer is already known after the first child. Can you return false right there?

The value is decided, but the contract isn’t met: the cursor is still inside the &(…). The caller would then read the leftover ,t) as if it were its own. Try |(&(f,t),f): the early return gives true. You may skip evaluating the rest, but you still have to move past it.

3. On a 2·104-character input, how deep can the recursion get?

Each level of nesting costs at least 3 characters (!( … )), so the depth is at most n/3 ≈ 6,667. Those frames are tiny compared with the default stack, and the test runs exactly that case. Time is O(n), because every character is consumed exactly once.
