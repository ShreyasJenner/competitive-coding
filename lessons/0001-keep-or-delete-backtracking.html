Keep or Delete

Backtracking with a budget, using LeetCode 301 “Remove Invalid Parentheses”

Your win today: an accepted solution to LC 301 that you wrote yourself, and a reusable way to think about backtracking: a recursion tree where every node is a choice, and pruning cuts off branches that can’t reach a good leaf.

The task: given a string of (, ) and letters, remove the minimum number of parentheses so it becomes valid, and return every distinct result. For example, "()())()" becomes ["(())()", "()()()"].

The words “minimum” and “every” give away the technique. “Every” means enumeration, so you need a complete search. “Minimum” tells you how to keep that search small.

1. Know your budget before you search

A single left-to-right scan tells you exactly how many of each bracket must go. Keep a balance open as you scan:

  • ( → open++
  • ) with open > 0 → it matches something, so open--
  • ) with open == 0 → nothing can ever match it, so rmR++
  • At the end, whatever is still open is unmatched: rmL = open
This scan is LeetCode 921 (“Minimum Add to Make Parentheses Valid”) in disguise, as walkccc’s write-up points out.

rmL + rmR is the minimum number of removals. So the search only ever removes exactly rmL opens and rmR closes. Those two numbers are its budget.

For "())(()": ( open=1 · ) open=0 · ) with open=0, so rmR=1 · ( open=1 · ( open=2 · ) open=1. At the end open=1, so rmL=1.

2. The search is a tree of choices

Walk the string by index i. Each parenthesis gives two choices, keep it or delete it. Letters are always kept. That makes a binary recursion tree of depth n, and each root-to-leaf path builds one candidate string. This is the same shape as generating subsets in the Competitive Programmer’s Handbook, §5.1: each element is either in or out.

Two passes, two meanings. The search runs after the scan in Part 1 has finished. The scan’s rmL/rmR count up from 0 and become the starting budget. Inside the search they mean deletions still allowed and only count down, by one each time a bracket is deleted.

Without pruning that is 2n leaves. Each pruning rule below cuts off a branch that cannot lead to a valid answer:

ChoiceAllowed only ifWhy
delete (rmL > 0Otherwise you’d remove more than the minimum
delete )rmR > 0Same reason
keep )open > 0An unmatched ) can never be fixed later
keep (alwaysA later ) might match it
accept leafopen == 0 && rmL == 0 && rmR == 0Balanced, with the whole budget spent

3. Different paths, same string

The figure shows the last trap. Deleting either of the two ) gives "()", but the problem wants distinct results. For your first version, put every accepted path into a std::set<std::string> and convert it to a vector at the end. Inputs are at most 25 characters (constraints), so a set costs almost nothing here.

4. Check yourself

Try to answer from memory before you scroll back up. The effort of recalling is what makes it stick.

1. Why compute rmL and rmR before searching?

The budget does two jobs. It guarantees every accepted string uses the minimum number of removals, and it prunes any branch that would overspend.

2. At index i you see ) and open == 0. Which branches survive?

Keeping it would make the balance negative, which no later character can repair. The only branch left is delete, and that needs budget.

3. Two different leaves produce the same string. What should you do?

Duplicates are expected whenever equal adjacent characters can be deleted. A set removes them. A cleverer skip rule exists (see the stretch goal below).

4. What state must each recursive call know?

Each pruning rule reads one of these: i picks the character, open guards keeping ), and rmL/rmR guard deletions. The path is the answer you’re building.

If you get stuck, open the hints one at a time. Each hint gives away a little more.

Hint 1: the recursion skeleton

Store s, the current path and the result set as class members. Then dfs only needs (i, open, rmL, rmR). The base case is i == s.size().

Hint 2: order of the branches

First try deleting s[i] if it’s a bracket and the budget allows. Then try keeping it, but bail out before keeping a ) when open == 0.

Hint 3: choose / explore / un-choose

Keeping a character is path.push_back(c), then recurse, then path.pop_back(). This is the backtracking pattern: undo your choice so the sibling branch sees a clean state. See the reference sheet.

Stretch goal (optional). Drop the std::set. Instead, avoid duplicates by never deleting a character right after you kept an identical one. Can you convince yourself why that works? If you’d like to see a different technique: this problem can also be solved with BFS. Treat each string as a graph node, link it to every string with one character removed, and stop at the first level that contains a valid string. That’s a natural bridge into graphs.
