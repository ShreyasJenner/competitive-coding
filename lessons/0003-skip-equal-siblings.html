Skip Equal Siblings

Your 301 is correct, but its std::set is hiding wasted work

Your win today: delete std::set from 301 and add one condition, so that every answer is built exactly once. On "((((((((((((((((" your dfs currently makes 131,071 calls. Afterwards it makes 153.

1. Predict first

Your dfs reaches accepted leaves and inserts them into a set. The set quietly drops any string it already has. How many times is each answer actually built? Work it out on paper. The budget for each input is in brackets.

How many accepted leaves produce this answer in your current 301?

"()))))"
"((()"
"((a))))"
"())(()"

In "((a))))" the four ) form one run, and two of them must go. Any 2 of the 4 will do, which gives C(4,2) = 6 leaves that all spell "((a))". In "())(()" you delete one of the )) and one of the ((, so 2 × 2 = 4.

2. Which one you delete doesn’t matter

Within a run (consecutive identical characters), deleting the 1st ) or the 3rd ) leaves the same string. The only thing that matters is how many you delete from the run. So choose one representative for each count, and let the search build only that one:

The rule: in each run, only delete from the front. In keep/delete terms: if s[i] == s[i-1] and you kept s[i-1], then s[i] gets no delete child. Once you keep one character from a run, you keep the rest of it.

This can’t lose an answer. Take any deletion pattern, slide each run’s deletions to the front of that run, and you get the same string. So every answer still has one pattern the rule allows. The rule also helps more than the set did. The set removed duplicates after they were built, but the rule never enters those subtrees in the first place.

This is the “skip equal siblings” trick. Solutions that loop over choices write it as if (i > start && s[i] == s[i-1]) continue;, as in LC 90 Subsets II. Your binary keep/delete tree needs the version above.

3. See it

Each row shows one accepted leaf, with the deleted characters struck. Turn the rule on and watch which pattern survives in each group.

Try "((((((((((((((((". Without the rule, every subset of the 16 brackets is a different path, which gives 217−1 calls for one empty string.

4. Check yourself

1. s = "())", rmR = 1. Which deletion does the rule keep?

Indices 1–2 are a run of ), so deletion comes from the front. Deleting index 2 is blocked whenever index 1 was kept.

2. Why can the rule never lose a valid answer?

Sliding deletions within a run doesn’t change the resulting string, so every answer keeps at least one pattern the rule allows.

3. Why do calls drop from 131,071 to 153, and not just the number of leaves?

A blocked delete child is never called, so its entire subtree is never searched. This is the same kind of pruning as Lesson 1’s budget. std::set could only throw away results after the work was done.

Hint 1

At index i, what does dfs need to know that it doesn’t currently know?

Hint 2

Whether s[i-1] was kept or deleted. Every call site already knows which kind of child it is creating, so it can pass that information down as a parameter, just like the budget.

Hint 3

Before, the delete child existed when “the budget is left”. Now it exists when “the budget is left and not (same character as before and that one was kept)”. Letters don’t need it, because they are never deleted.

There is more than one correct canonical choice. If you find a different rule, the random test will tell you whether it holds.
