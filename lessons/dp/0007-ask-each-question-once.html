Ask Each Question Once

LC 198 House Robber: write the brute-force recursion first, find the questions it asks twice, and answer each one only once

Your win today: turn an exponential brute force into an O(n) solution by adding three lines, without changing its logic. This is the whole idea of dynamic programming, and the mission’s “spot the redundant work” skill in its purest form.

0. Attempt it cold

You like to try first, so try first. usr/src/leetcode/198.cpp is a starter that returns 0, and ./test.sh 198 runs 20 cases: the examples, one or two houses, streets where the best plan skips two houses in a row, 1,000 random streets checked against a brute force over every set of houses, and six streets of 99 or 100 houses.

Every case has a 2-second limit. If your code is correct but asks the same question many times, it passes the small cases and then prints still running after 2 s on the first 100-house street. That is not a logic bug. It is today’s lesson, so read on from §1. If you’re fully green, skim to §4 and do the quizzes anyway.

1. Return your own answer, again

In 236, f(t) answered for t’s subtree and nothing else. In 695, a fill returned its island’s size. Here the “subtree” is the rest of the street:

best(i) = the most money you can rob from houses i, i+1, …, n−1, ignoring every house before i. The answer is best(0).

CPH puts it this way: “formulate the problem recursively so that the solution to the problem can be calculated from solutions to smaller subproblems” (ch. 7, PDF p. 76). Use only the contract to fill these in. Start at the end of the street, where the answer is obvious, and work back:

nums = [2, 7, 9, 3, 1] (house 0 holds 2, house 4 holds 1)

Only house 4 is left, so rob it: 1. From house 3, take either 3 or 1, not both: 3. From house 2, rob 9 and then house 4: 10. From house 1, robbing 7 leaves houses 3 onward (3 more), which ties with skipping it (10). From house 0, robbing 2 leaves houses 2 onward (10 more): 12. Notice that you never re-solved a later street. You reused the number you had just written down. Keep that in mind for §3.

2. One choice per house

At house i there are exactly two options, and the contract gives each one a value.

1. You rob house i. Which house is the next one you may consider?

House i+1 is next door and off limits. From i+2 onward, anything is allowed, and that is exactly what best(i+2) promises to handle. Houses before i aren’t this call’s business, as the contract says.

The recurrence (open once you’ve written yours) 
best(i) = 0                                     if i ≥ n   (no houses left)
best(i) = max( best(i+1),                       skip house i
               nums[i] + best(i+2) )            rob house i

Compare CPH’s coin problem, solve(x) = min over c of solve(x−c) + 1 (PDF p. 76): it has the same shape, with more choices and a min. Written straight into C++, this is a correct solution. It is also hopeless at 100 houses. §3 shows why.

3. Find the repeated work

best(0) calls best(1) and best(2). But best(1) also calls best(2). Predict before you look: with 6 houses and no memo, how many times is each call made?

6 houses, plain recursion, starting from best(0):

Every call on i comes from a call on i−1 (skip) or on i−2 (rob), so count(i) = count(i−1) + count(i−2): 1, 1, 2, 3, 5, 8, … These are the Fibonacci numbers, which grow by a factor of about 1.6 per house. In CPH’s words, the plain version “is not efficient, because there may be an exponential number of ways” (PDF p. 77).

Now check it. Click best(4) in the tally to light up every call on it. Each lit subtree is identical work, because best(4) depends only on 4, never on how you got there. Then tick memo.

This is the core idea. A call’s answer depends only on its arguments, so the same argument always gives the same answer. There are only n different questions (best(0) to best(n−1)), yet the plain recursion asks them about 1021 times. The redundant work is every call after the first one on each argument. CPH calls these overlapping subproblems (PDF p. 75). In 236 every call was on a different node, so there was nothing to save.

4. Memoization: write it down the first time

“The values of the function are stored in an array after calculating them. For each parameter, the value of the function is calculated recursively only once, and after this, the value can be directly retrieved from the array.” (CPH ch. 7, PDF p. 77)

That takes three changes to the plain recursion: an array indexed by the argument, a lookup before the work, and a store after it. The logic in between doesn’t change. CPH uses a separate ready[x] array to mark which answers are stored. Most people use one array and a value that can never be a real answer.

2. Your memo starts full of 0, and best(i) begins with if (memo[i]) return memo[i];. What happens on 100 empty houses?

Every answer on that street is 0, so a stored answer looks the same as “not done yet”, and every call recomputes. The memo is there, but it never hits. Use -1, since money is never negative. The test’s “100 houses, all empty” case is there to catch exactly this.

3. With the memo, what does best(0) cost on n houses?

Each of the n arguments does real work once: two calls and a max. Every other call is an O(1) lookup, and there are at most two per real call. The memo has n entries, and the stack goes n deep (best(0) → best(1) → …). The widget above shows the counts: 201 calls for 100 houses.

5. Optional: the same table, filled by a loop

The memo is a table best[0..n−1]. You can fill it without recursion, as long as every entry is filled after the entries it reads. CPH notes that “most competitive programmers prefer this implementation, because it is shorter and has lower constant factors”, but that “it is often easier to think about dynamic programming solutions in terms of recursive functions” (PDF p. 78). So think recursively, then convert if you like.

4. To fill best[] with a loop instead of recursion, which order works?

best[i] reads best[i+1] and best[i+2], so both must already be filled. Fill them by going right to left, which is what you did by hand in §1. (If you define the state as “houses 0..i” instead, the loop runs left to right. Both are fine, but the direction must match the definition.)

Stretch: the loop reads only the next two entries, so two variables can replace the whole array. That gives O(1) memory.

6. Your turn: usr/src/leetcode/198.cpp

  1. Write the contract as a comment, in your own words.
  2. Write the plain recursion first, even if you’ve already spotted the fix. Run ./test.sh 198. Predict how many cases pass before the timeout, then check.
  3. Add the memo (array, lookup, store). Expect 20/20.
  4. Predict which case fails if you start the memo at 0 (quiz 2). Try it.
  5. Optional: rewrite it as the loop in §5, then with two variables.

One difference from 236: rob(nums) doesn’t take an index, so it can’t be best(i) the way lowestCommonAncestor was f(t). You’ll need a helper. Remember 236’s first attempt: pass the vector by reference.

Hint 1

What is best(i) when i ≥ n? Note that i can reach n+1, because robbing house n−1 asks for best(n+1).

Hint 2

Skipping house i is worth best(i+1). Robbing it is worth nums[i] plus what quiz 1 says. Return the larger.

Hint 3

Keep a member std::vector<int> memo. In rob, set it to n copies of -1. In the helper, after the base case, return memo[i] if it isn’t -1, and store into it just before you return.
