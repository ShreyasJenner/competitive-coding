Two Answers per Node

LC 337 House Robber III: when a parent needs more than one fact about its child, the child returns more than one value, and the repeated work disappears without a memo

Your win today: solve a DP on a tree in O(n) with one post-order pass and no memo, by making each call return a pair. This combines Lesson 6’s “ask your children” with Lesson 7’s “ask each question once”, using the “robbed / not robbed” state you invented for 198.

0. Attempt it cold

usr/src/leetcode/337.cpp is a starter that returns 0, and ./test.sh 337 runs 15 cases: the examples, small trees where the best plan skips a level or mixes levels, a tree where two nodes share a value but have different answers, 400 random trees checked against a brute force over every set of nodes, an 8,191-node complete tree, a random 10,000-node tree, and two 10,000-node vines. As in 198, every case has a 2-second limit.

Try it before reading on. If you hit still running after 2 s, §2 explains why.

1. Warm-up from 198

1. In your memoised best(i), why must the i >= n check come before the memo lookup?

memo has n entries, but the recursion asks for best(n) and best(n+1). That was your crash. Base cases come first because they are the calls that have no memo slot. The same applies today: nullptr has no entry in anything.

2. The obvious contract, and its repeated work

Use Lesson 6’s shape: f(t) = the most money from t’s subtree. Lesson 7 gives the choice. Rob t, and its children are off limits, so add the grandchildren’s f. Or skip t, and take f(left) + f(right).

Fill in from the bottom up:

Robbing 4 gives 4, and skipping it gives its children 1 + 3 = 4, so f(4) is 4. Robbing 5 gives 5, and skipping it gives 1, so 5. Robbing the root gives 3 + its grandchildren 1 + 3 + 1 = 8, and skipping it gives f(4) + f(5) = 9. The answer is 9.

That is correct, but look at who asks about each node. Node 4’s left child is asked once by node 4 (“skip 4”) and again by the root (“rob 3, take grandchildren”). Every node gets asked by its parent and by its grandparent. On a long vine, where each node has one child, that is LC 198’s plain recursion exactly: number the nodes by depth, and f(i) calls f(i+1) and f(i+2).

The test’s 10,000-node vine has the same blow-up as your 100-house street, only worse. There are two fixes.

3. Fix A: a memo keyed by the node

The state is now a node rather than an index, so the memo is a map from node to answer: std::unordered_map<TreeNode*, int>. As before, put the base case first, look up before the work, and store after it.

2. You key the memo by t->val instead of by t. What goes wrong?

The memo’s key has to be everything the answer depends on. Here the answer depends on the whole subtree, not on the node’s value. Two nodes with value 4 can sit on top of very different subtrees, which is exactly the test’s [0,4,4,9,null,null,null,9] case. The pointer names the subtree, which is the same lesson as 236’s “compare pointers, not values”.

Fix A works, and it is O(n). But it’s a patch on a contract that asks too much. The root needs facts about its grandchildren only because f(child) doesn’t say whether the child was robbed.

4. Fix B: return both answers

In your 198 solution, best[i] meant “house i is robbed”. Keep that idea and add its partner. CPH does the same in its tree-diameter algorithm: “We calculate for each node x two values” (ch. 14, PDF p. 146). Write your contract for g(t) down before opening the box.

The pair contract (open once you’ve written yours)

g(t) returns two numbers about t’s subtree:

ValueMeansFrom the children’s pairs
robthe best if t is robbedt->val + left.skip + right.skip
skipthe best if t isn’tmax(left.rob, left.skip) + max(right.rob, right.skip)

The base case is g(nullptr) = (0, 0), and the answer is max of g(root)’s pair. Each node is called exactly once, by its parent, so there is no repeated work and nothing to memoise. The skip-or-rob choice from 198 is now made one level up, by the parent.

3. t->val is 6. Its children returned (5, 2) and (3, 4) as (rob, skip). What does g(t) return?

Robbing t forces both children to be skipped: 6 + 2 + 4 = 12. Skipping t lets each child take its better half: max(5, 2) + max(3, 4) = 5 + 4 = 9. Note that the right child does better skipped (4 > 3). “Robbed” is not always the bigger number.

LeetCode’s example 1, [3,2,3,null,3,null,1]. The leaves 3 and 1 return (3, 0) and (1, 0).

g(2)
g(right 3)
g(root 3)

Node 2 has only a right leaf 3. Robbing it gives 2 + 0 + 0 = 2, and skipping it gives max(3, 0) = 3. The right-hand 3 has a leaf 1: robbed it is 3, skipped it is 1. At the root, robbing gives 3 + 3 + 1 = 7, and skipping gives max(2, 3) + max(3, 1) = 6. The answer is 7: the root plus the two bottom leaves.

4. What does the pair version cost on n nodes with height h?

One call per node, each doing O(1) work with its children’s pairs: that is 236’s cost. No map is needed, because no question is asked twice. On the 10,000-node vine, h = n, which is why the test stops there and not at 105.

Name check: picking nodes so that no two are joined by an edge, and maximising their total, is the maximum-weight independent set. CPH notes that finding a maximum independent set “in a general graph is a NP-hard problem” (PDF p. 200). On a tree, these two numbers per node make it linear.

Hint 1

What pair does an empty subtree return? Neither option has any money in it.

Hint 2

If t is robbed, neither child may be. Which half of each child’s pair is allowed?

Hint 3

If t is skipped, each child is free to be robbed or not, independently of the other. Take each child’s better half.
